# [기능] 마지막 로그인 계정으로 계속하기

> 커밋 `17a61b2` (`feature/ui-foundation`, 푸시 전). 브라우저 확인은 아직 안 함.

## 동작

| 화면 | 바뀐 것 |
|---|---|
| 로그인 `/login` | 마지막으로 로그인한 이메일을 입력칸에 미리 채운다 (이미 입력한 값이 있으면 그대로) |
| 회원가입 `/signup` | 마지막 로그인 이메일이 있으면 맨 위에 "{email}(으)로 계속하기" 버튼과 "또는 새 계정 만들기". 버튼을 누르면 인증 코드를 보내고 `/signup/verify`로 이동. 이때 이름 입력 "다음" 버튼은 보조 스타일 |
| 인증 `/signup/verify` | 기존 계정으로 로그인 완료(`signedIn`)되면 이메일을 저장 |

**인증은 줄이지 않는다** — 버튼은 이메일 입력을 대신할 뿐, OTP 확인은 그대로 거친다.

## 구현

- `lib/authFlow.ts` `saveLastLoginEmail` · `readLastLoginEmail` — `localStorage`의 `lastLoginEmail`. 로그아웃해도 남는다 (그래야 "계속하기"를 쓸 수 있음). 저장소 접근이 막힌 브라우저에선 조용히 무시.
- 회원가입 화면은 `useSyncExternalStore`로 읽는다 — 서버 렌더에선 `null`, 브라우저에선 저장된 값이라 하이드레이션 불일치가 없다.
- 인증 코드 발송 실패 시 "인증 코드를 보내지 못했어요. 잠시 후 다시 시도해주세요."

## 알아둘 것

- 공용 PC에서는 다음 사람에게 이메일이 보인다. 지우는 버튼은 없다 (필요하면 추가).
- 저장 시점은 `/signup/verify`의 로그인 완료다. 로그인 화면도 같은 인증 화면을 거치므로 로그인할 때마다 갱신된다. 신규 가입 완료 시에는 저장하지 않는다.
