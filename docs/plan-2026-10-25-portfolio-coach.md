# [기획] 포트폴리오 코치 기능 — 프론트엔드

- 작성일: 2026.10.25
- 상태: 기획 (구현 전)
- 짝 문서: 백엔드 `api/docs/plan-2026-10-25-portfolio-coach.md` (데이터 모델·API 명세는 그쪽 기준)

## 1. 왜 하는가

### 포지셔닝

링커리어·잡코리아는 **취업 직전** 학생이 공고를 찾고 지원하는 곳이다. Pofol은 그 **이전 단계** —
1~3학년이 흩어진 프로젝트를 정리하고, 부족한 점을 점검하고, "지원할 수 있는 상태"의 포트폴리오를
만드는 곳으로 자리 잡는다.

> 한 줄 정의: **취업 준비 전, 내 GitHub를 포트폴리오로 바꿔주는 곳**

| | 링커리어·잡코리아 | Pofol |
| --- | --- | --- |
| 사용 시점 | 취업 직전 | 1~3학년, 준비 단계 |
| 하는 일 | 공고 탐색·지원 | 프로젝트 정리 → 점검 → 보완 |
| 결과물 | 지원서 | 검증된 포트폴리오 · 이력서 |

### 근거 (발표 자료와 동일)

- 채용공고의 82%가 경력직만 채용, 신입만 채용은 2.6% (대한상공회의소, 2025 상반기)
- 기업 85%가 "경력 있는 신입" 선호 (고용노동부·한국고용정보원, 2025)
- 취준생 80.7%가 "업무 경험·경력개발 기회 부족"을 최대 애로로 꼽음 (경총, 2025)
- 계속 운영 중인 사이드 프로젝트는 26.2% (잡코리아 개발자 설문)

### 원칙

- **커뮤니티는 보조.** 피드·댓글·팔로우는 포트폴리오에 대한 피드백 수단으로만 둔다.
- **점수보다 할 일 목록.** 분석 결과는 "N점"이 아니라 해결하면 체크되는 체크리스트로 보여준다.
- **근거를 보여준다.** AI가 쓴 문장과 GitHub·팀원 확인으로 검증된 사실을 화면에서 구분한다.
- **학생은 무료.** 핵심 기능은 무료, AI 분석만 횟수 제한(월 N회)으로 비용을 관리한다.

## 3. 기능별 화면 설계

### 3.1 GitHub 레포 요약 대시보드

**위치:** `/profile` 에 "GitHub" 탭 추가 → `app/[locale]/profile/_components/GitHubTab.tsx`
(타인 프로필 `/profile/[id]`에서는 공개 설정한 항목만 노출)

**표시 내용**

- 총 레포 수 (직접 만든 것 / 포크 구분), 총 스타 수
- 언어 비중 막대 (레포별 `languages` 합산, 상위 5개 + 기타)
- 최근 활동: 마지막 push 시각, 최근 90일 활동한 레포 수
- 레포 목록 카드: 이름, 설명, 주 언어, 스타, 마지막 push, 점검 경고 개수

**상태 처리**

- GitHub 미연동: 연동 유도 카드 (기존 `app/api/auth/github/connect` 연동 흐름 재사용)
- 분석 중: `Skeleton` 컴포넌트로 카드 자리 표시
- 토큰 만료(백엔드 401/403 메시지): "GitHub 재연동이 필요합니다" + 재연동 버튼
- 마지막 분석 시각과 [다시 분석] 버튼 (백엔드 캐시 TTL 때문에 즉시 반영 안 될 수 있음을 안내)

### 3.2 레포 점검 체크리스트

대시보드 아래 "정리할 것" 섹션. 레포별로 펼치는 아코디언 + 전체 요약 칩("README 없음 4개").

| 항목 | 기준 (백엔드 규칙과 동일) | 해결 가이드 |
| --- | --- | --- |
| README 없음 | README 파일 없음 | README 템플릿 복사 버튼 |
| 설명·토픽 비어 있음 | description / topics 비어 있음 | GitHub 설정 링크 |
| 배포 링크 없음 | homepage 비어 있음 | 배포했다면 homepage 등록 안내 |
| 테스트 없음 | test / tests / `__tests__` / `src/test` 폴더 없음 | 언어별 테스트 시작 가이드 |
| 커밋이 너무 적음 | 커밋 2개 이하 | 비공개 또는 보관(archive) 권장 |
| 커밋 메시지 품질 | 최근 커밋 대부분이 "update", "수정" 등 | 커밋 컨벤션 예시 |
| 포크 위주 | 직접 만든 레포 비율이 낮음 | 개인 프로젝트 시작 권유 |

- 사용자가 GitHub에서 고친 뒤 [다시 분석]하면 체크가 채워진다 → 재방문 동기.
- "이 항목 무시" 토글 (예: 연습용 레포)은 백엔드에 저장.

### 3.3 프로필 README 점검 · 초안 생성 · 꾸미기 추천

**점검:** 백엔드가 `{login}/{login}` 레포의 README 존재 여부를 알려준다. 없으면 대시보드 상단에
"GitHub 프로필 소개가 없습니다" 배너.

**초안 생성 (AI):**

- 입력: 희망 직무(선택), 방향성 분석 결과(3.4), 대표 프로젝트, 기술 스택
- 출력: 마크다운. 미리보기 + 편집 가능한 textarea + [복사] 버튼
- 1차는 **복사 방식만** 제공. GitHub에 직접 커밋하는 기능은 `public_repo` 권한으로 가능하지만,
  사용자 GitHub에 쓰는 동작이므로 2차에 별도 확인 모달과 함께 검토한다.

**구성 순서 (템플릿의 섹션 순서):** 한 줄 소개 → 대표 프로젝트 → 기술 스택 → 연락처 → 통계·장식

**꾸미기 추천 (체크해서 초안에 삽입):**

| 요소 | 도구 | 비고 |
| --- | --- | --- |
| 기술 스택 뱃지 | shields.io | 기본 포함. `skill_list`가 이미 shields.io 뱃지 정보를 갖고 있음 |
| 통계 카드 | github-readme-stats | 공용 인스턴스는 느리거나 막힐 수 있어 자체 배포 안내 |
| 연속 기여 | github-readme-streak-stats | 선택 |
| 헤더 배너 | capsule-render | 선택 |
| 알고리즘 티어 | solved.ac 뱃지 | 백준 아이디 입력 시 |
| 블로그 최신 글 | blog-post-workflow (GitHub Actions) | velog·티스토리 RSS, 워크플로 파일 함께 제공 |

장식이 과하면 역효과라는 안내 문구를 함께 둔다.

### 3.4 대표 프로젝트 Top 3 · 방향성 분석

- **Top 3:** 백엔드 점수 순 상위 3개. 카드마다 **점수 근거**를 칩으로 표시
  (예: "README 충실", "배포됨", "3인 협업", "6주 개발"). 점수 숫자 자체는 노출하지 않는다.
  [대표 프로젝트로 고정] → 프로필 상단에 표시.
- **방향성 (AI):** 2~3문장 요약 + 근거 언어/프레임워크 칩.
  예: "Spring·Java 중심의 백엔드 성향, 최근 Next.js로 확장 중".
  희망 직무를 고르면 "직무와 맞는 점 / 보완할 점"을 함께 보여준다.

### 3.5 발표자료 뷰어 (PDF · 구글 슬라이드)

게시글 작성(`board/write`)에 "발표자료" 섹션 추가. 둘 중 하나를 선택한다.

**A. PDF 업로드 (기본)**

- 현재 썸네일 업로드(`app/api/upload/thumbnail`)는 서버 경유라 Vercel 함수 본문 한도(약 4.5MB)에
  걸린다 (`lib/uploadLimits.ts`의 4MB 제한). PDF는 **브라우저 → Vercel Blob 직접 업로드**로 한다.
  - 클라이언트: `@vercel/blob/client`의 `upload()`
  - 서버: `app/api/upload/document/route.ts`에서 `handleUpload()`로 토큰 발급.
    `onBeforeGenerateToken`에서 로그인·`application/pdf`·최대 30MB 검증, 기존 `rateLimit` 적용
  - 상수는 `lib/uploadLimits.ts`에 `MAX_DOCUMENT_BYTES` 등으로 추가
- 뷰어: pdf.js 기반(`react-pdf` 등)으로 페이지 넘김 + 전체화면. 클라이언트 컴포넌트로 지연 로딩
- 첫 페이지를 썸네일 후보로 제안 (기존 썸네일 흐름과 연결)

**B. 구글 슬라이드 링크**

- 사용자가 공유 링크를 붙여넣으면 `docs.google.com/presentation/d/{id}/...`에서 id를 뽑아
  `https://docs.google.com/presentation/d/{id}/embed`로 바꿔 iframe으로 표시
- 비공개 슬라이드는 표시되지 않으므로 "파일 → 공유 → 웹에 게시" 안내를 함께 둔다
- 형식 검증은 프론트와 백엔드 양쪽에서 (임의 URL iframe 방지)

**검토 후 보류:** PPTX를 그대로 받아 변환하는 방식(서버 변환, MS Office 웹 뷰어, 구글 드라이브
자동 변환)은 외부 서비스 의존이나 OAuth 범위 확대가 필요해 이번 범위에서 제외한다. PowerPoint·
Keynote·구글 슬라이드 모두 PDF 내보내기가 한 번에 되므로 A로 충분하다.

### 3.6 프로필 사진 업로드

- `user_profile.avatar_url` 컬럼과 응답 필드는 이미 있고, 수정 API·업로드 UI가 없다
  (`docs/fix-2026-07-22-board-detail-ssr-crash.md`에 후속 작업으로 남아 있음).
- `ProfileEditModal.tsx`에 사진 선택 + 원형 크롭 미리보기 추가
- 업로드는 썸네일 라우트 패턴을 재사용한 `app/api/upload/avatar/route.ts` (2MB, png/jpg/webp)
- 이력서 PDF에서는 사진 표시를 켜고 끌 수 있게 한다 (블라인드 채용 대응)

### 3.7 AI 이력서

**흐름:** 설문 → 자동 분석 → AI 초안 → 본인 수정 → PDF 내보내기

1. **설문 (1분, 5문항):** 희망 직무, 관심 분야, 팀에서 주로 맡는 역할, 강점 키워드 3개, 한 줄 목표
2. **자동 수집:** Pofol 게시글, GitHub 분석 결과(3.1~3.4), 보유 기술 스택, 학교 인증
3. **AI 초안:** "어떤 개발자인가" 한 줄 정의, 프로젝트별 역할·성과, 기술 스택 지도
4. **편집:** 섹션별 편집, 여러 버전 저장
5. **내보내기:** 브라우저 인쇄용 레이아웃(`@media print`)으로 PDF 저장 → 별도 PDF 라이브러리 불필요

**검증 배지:** 문장마다 출처를 표시한다.

- ✅ 검증됨: GitHub 데이터(커밋 수, 기간)나 팀원 확인으로 뒷받침되는 사실
- ✏️ 본인 작성 / 🤖 AI 작성: 근거가 없는 서술

**위치:** `app/[locale]/resume/` (목록), `app/[locale]/resume/[id]/` (편집)

## 4. AI 호출 구조

기존 `app/api/ai/summarize`, `app/api/ai/thumbnail`과 같은 패턴(Next 라우트 + OpenAI + `rateLimit`)을 따른다.

| 라우트 | 입력 | 출력 |
| --- | --- | --- |
| `app/api/ai/github-direction` | 백엔드 분석 요약(JSON) + 희망 직무 | 방향성 요약, 보완점 |
| `app/api/ai/profile-readme` | 방향성 + 대표 프로젝트 + 스택 + 선택한 꾸미기 요소 | 마크다운 |
| `app/api/ai/resume` | 설문 + 분석 결과 + 게시글 | 섹션별 초안(JSON) |

- **코드 원문은 보내지 않는다.** 백엔드가 만든 요약(메타데이터·README 일부)만 보낸다 → 1회 비용 수 원 수준
- 모델은 기존 `summarize` 라우트와 같은 `gpt-4o-mini`로 시작하고, 품질이 부족하면 상위 모델을 검토한다
- 결과는 백엔드에 저장해서 같은 입력으로 다시 호출하지 않는다
- 사용 횟수 제한(월 N회)은 백엔드가 집계하고, 라우트는 호출 전에 남은 횟수를 확인한다
- 입력 검증은 `lib/aiInput.ts`에 파서를 추가해 기존 방식과 맞춘다

## 6. 이후 단계 (수익화)

학생 기능은 무료로 두고, 사용자가 쌓인 뒤 아래를 붙인다. 화면 설계는 그 시점에 별도 문서로.

- **학과 쇼케이스:** 학교 인증 정보로 학과별 졸업작품·캡스톤 모음 페이지 (학교 라이선스)
- **기업 챌린지:** 기업이 실무 과제를 올리고 결과물이 포트폴리오로 남음 (기업 후원)
- **스카우트:** 검증된 포트폴리오 열람·제안 (기업 이용권, 메인 수익원)
- **학생 프리미엄 (소액, 보조):** 이력서 여러 버전, 직무 맞춤 심층 분석, 업로드 용량 확대
- **광고:** 교육·부트캠프 등 관련 광고만 최소한으로. "신뢰" 이미지와 충돌하므로 메인 수익원으로 두지 않는다
